# entity-core-protocol-nim

A full **core-protocol** Entity Core peer in **Nim** (2.2.x, ARC/ORC). Generated by the
keystone `/entity-rosetta` pipeline as a **Tier-3 corroboration / generator-robustness peer**
on a fresh compiles-to-C substrate — its headline idiom axis is the **compile-time
metaprogramming codec** (the canonical ECF encoder/decoder dispatched on major-type at compile
time via `macro`/`template`/`static:`, zero runtime reflection — the Zig `comptime` result on
a garbage-collected, native-C-FFI substrate), plus a **fixed-width `uint64` head-form** carrier
and a **native `{.importc.}` libsodium crypto floor**.

**Conformance:** `validate-peer --profile core` → **682 · 0F @ `cc1970f`**
(293 P / 293 W / 0 F / 96 S) — `Result: PASS`.
See [`status/CONFORMANCE-REPORT.md`](status/CONFORMANCE-REPORT.md) for the full per-category
table and [`status/CONFORMANCE-REPORT.json`](status/CONFORMANCE-REPORT.json) for the machine
record. Tracks **ENTITY-CORE-PROTOCOL v0.8.0 (V8)** (core wire byte-unchanged across the
V7→V8 cutover).

> **Honest framing (ADR-0012).** Nim shares the generation lineage of the keystone cohort —
> a Nim peer passing the author's vectors is **cohort-consistent corroboration, not independent
> convergence**. The spec-discovery well is dry on the current wire surface; this peer's value
> is (a) corroborating the settled cohort results on a fresh substrate and (b) exercising
> generator robustness on Nim's genuinely novel idiom axes (compile-time-metaprogrammed codec;
> native-C-interop crypto; ARC/ORC deterministic GC). A fresh spec finding would be upside, not
> the expectation — none surfaced. Every conformance number here is oracle-pinned
> (`N·0F @ cc1970f` with its P/W/F/S breakdown); a skip counts as a failure until bisected (all
> 96 are, in the report).

> Scope: **core Layers 0–4** (substrate, identity, interaction, capability, bootstrap). No
> standard extension (TREE, CONTENT, IDENTITY, ATTESTATION, QUORUM, REGISTRY, RELAY) is
> implemented — the extension surface stops at the dispatcher interface. This is a *provided*
> conformance peer, not a mandate; anyone may build a ground-up implementation.

## What this peer is (the idiom axes)

Nim compiles to C, is statically typed, and is garbage-collected via **ARC/ORC** (deterministic
ref-counting + a cycle collector — destructors run at scope exit, no stop-the-world pause). Its
distinctive generator-stress axis is **compile-time metaprogramming**: the canonical ECF codec
(`src/ecf.nim`) selects the CBOR major type and emits the head at **compile time** through
`macro` / `template` / `static:` — zero runtime reflection, the same "render from the model"
pattern Zig reached via `comptime`, carried onto a GC'd, native-C-backend substrate. The
`[2⁶³, 2⁶⁴−1]` fixed-width head-form self-test is proven twice: at compile time (a `static:`
block executes the encoder in the Nim VM — a build only succeeds if the asserts hold) **and** at
run time (`tests/tconformance.nim`).

The **numeric carrier is fixed-width**: Nim's native `uint64` maps directly to the §1.5/§7.3
CBOR head form (the C `uint64_t` / Zig `u64` / C# `ulong` class — no bignum). A signed-`int64`
carrier would silently overflow the `[2⁶³, 2⁶⁴−1]` band, so that head-form self-test is
**mandatory** (and the codec builds with `--overflowChecks:on`, bound-checking every decoder
read since unsigned wraps silently).

Byte-vs-text is a **static type distinction** (unlike the Tcl EIAS trap): CBOR text-string
(mt3) = Nim `string` (a length-prefixed **byte** buffer — `len` is already a byte count, no
`encoding convertto` dance), byte-string (mt2) = `seq[byte]`, a distinct type. The major type is
sourced from the spec's field type definitions and carried in the typed model, never inferred
from a value.

## Codec & crypto floor (native — no C-ABI)

The shipped default peer needs **no `libentitycore_codec`** — the floor is fully native:

- **CBOR value codec — hand-rolled pure Nim** (`src/ecf.nim`): a `seq[byte]` encoder +
  `openArray[byte]` index-walk decoder, compile-time major-type dispatch. No Nim CBOR package
  gives canonical ECF (the `cbor` nimble package is a convenience DOM codec — none of the
  shortest-float f16 ladder / length-then-lex CTAP2 key order / recursive mt6-tag-reject /
  byte-string fidelity / full uint64 range, the A-005 pattern every native peer hit), so it is
  declined — A-NIM-001. Hand-rolling is both the faithful and the simpler path, and it exercises
  the compile-time-metaprogramming axis.
- **SHA-256 — system libsodium via native `{.importc.}` interop** (`src/crypto.nim`):
  `crypto_hash_sha256`. Nim compiles to C, so `{.importc.}` binding of libsodium is **in-process
  native interop** (the C peer's exact story), not a foreign-language bridge.
- **Ed25519 — system libsodium via `{.importc.}`**: `crypto_sign_seed_keypair` /
  `crypto_sign_detached` / `crypto_sign_verify_detached` (RFC-8032 deterministic detached
  signing). No audited pure-Nim EdDSA exists (nimcrypto ships SHA-2/HMAC but no Ed25519), so
  libsodium is the crypto floor — A-NIM-003. libsodium is ISC (Apache-compatible), statically
  linkable, present in the toolchain image.
- **base58 + LEB128 multikey varint — hand-rolled pure Nim** (`src/base58.nim`,
  `src/varint.nim`): a dep for something this small is pure liability; `wire-conformance`
  confirms both.

**Crypto floor:** Ed25519 + SHA-256 (system libsodium via native interop). **Ed448 + SHA-384
agility is deferred** — libsodium has no Ed448-Goldilocks (the same native gap C / Zig / OCaml
hit), so the agility family is an **opt-in sub-library** over either the sibling C-ABI
(`libentitycore_codec` `ec_ed448_*` / `ec_sha384`, the hybrid-FFI shape) or OpenSSL
`EVP_PKEY_ED448` — scoped so the shipped Ed25519+SHA floor peer stays one crypto library
(libsodium) + FFI-free of the entity C-ABI (A-NIM-004). Wire it when an adopter needs agility.

## Concurrency (§7b, structural)

The core peer runs Nim's stdlib **`asyncdispatch`** — async/await on a **single-threaded
cooperative event loop**. §7b store-safety is therefore **structural**: one event thread
serializes every store mutation, so there is no data race to guard (no mutex, no atomics) — the
store is a plain `std/tables` `Table` (the actor/CSP-class "free store-safety" reached via a
cooperative event loop — the PHP / Tcl / Dart / Julia result on a further substrate). §6.11
handler-initiated outbound-dispatch reentry is a plain event-loop turn keyed by `request_id`
through the transport's `io.pending` table — no cross-thread demux, no correlation-map tax
(A-NIM-006). Nim's real OS threads (`--threads:on`) are the noted alternative substrate, out of
scope for `--profile core`.

## Build

Container-bound (Podman, `nim-toolchain:latest`, `fedora:43` base, sealed-offline). The core
peer pulls **zero nimble registry packages** — `asyncdispatch` / `asyncnet` / `tables` /
`options` / `unittest` ship with the compiler, the codec / base58 / varint are hand-rolled
in-repo, and Ed25519+SHA-256 is system libsodium via `{.importc.}` — so `nim c` (Nim → C → gcc)
builds fully **offline** (`--network=none`) once the toolchain image exists.

```
. tools/podman-caps.sh   # from the keystone repo root — sets $PODMAN_RUN_CAPS (mandatory)

sh protocol-generator/nim/run-wire-conformance.sh   # S2 codec gate: v0.8.0 ECF corpus 71/71 byte-identical + [2⁶³,2⁶⁴−1] self-test
sh protocol-generator/nim/run-smoke.sh              # S3 peer machinery: two-peer loopback handshake + F31 auth-before-resolve + request_id demux
```

The S4 live-peer gate (`validate-peer --profile core`) and the origination-core reentry probe
run the Go oracle ELF alongside the Nim host inside the same image over loopback,
`--network=none`:

```
podman run $PODMAN_RUN_CAPS --rm --network=none -v "$PWD":/work:Z \
  entity-core-keystone/nim-toolchain:latest sh /work/protocol-generator/nim/run-s4.sh
podman run $PODMAN_RUN_CAPS --rm --network=none -v "$PWD":/work:Z \
  entity-core-keystone/nim-toolchain:latest sh /work/protocol-generator/nim/run-origination-core.sh
```

Conformance builds use `--mm:orc --overflowChecks:on -d:release` (deterministic GC + the
fixed-width overflow trap live + the throughput the §7b concurrency category needs).

## Run

```
nim c -d:release --mm:orc -o:host src/host.nim
./host --name NAME [--port N] [--validate] [--debug-open-grants]
```

Loads the peer's Ed25519 identity from `~/.entity/peers/NAME/keypair` (entity-core PEM = base64
of a 32-byte seed between BEGIN/END ENTITY PRIVATE KEY lines), binds loopback (`--port 0` =
auto-assign), prints a single `LISTENING 127.0.0.1:PORT peer_id=… validate=… open_grants=…`
readiness line, then runs the asyncdispatch event loop.

- **`--name NAME`** — persistent identity + peer-manager interop (the cohort convention). The
  keypair must exist at `~/.entity/peers/NAME/keypair` (the conformance harness provisions it;
  without `--name` the peer uses a random seed).
- **`--port N`** — listen port (`0`/omitted = auto-assign; default 7777).
- **`--validate`** — register the §7a `system/validate/*` conformance handlers (incl. the §6.11
  `dispatch-outbound` reentry). **OFF by default** — a standing outbound originator must not
  ship in production.
- **`--debug-open-grants`** — degenerate `default→*` seed policy. Deprecated (§6.9a); debug
  only, non-conformant.

**No runtime C-ABI dependency** for the floor peer. `libentitycore_codec` is needed **only** by
the opt-in Ed448 agility sub-library, which the floor peer never loads.

## Conformance detail

- **F = 0** on `validate-peer --profile core` (293 P / 293 W / 0 F / 96 S @ `cc1970f`,
  core-gate fingerprint `8261a033…`). The 293 WARN are non-gating: 292 are `type_system`
  non-floor `compute/*` extension vocabulary a **core** peer does not publish (matched-if-present)
  + 1 is `resource_bounds.r3_connection_flood` (§4.10(c) **SHOULD** — the peer survives 256 conns
  and serves the follow-up). All 96 skips are §9.0 extension carve-outs, auto-allowlisted and
  **bisected in the report — none masks a core primitive** (multisig / type_system / capability /
  concurrency / resource_bounds have 0 skips).
- **Genuine K-of-N multisig accept-path (non-vacuous):** live
  `multisig.valid_2of3_peer_signed_accepted` PASS (the oracle co-signs AS the peer via the
  provisioned keypair — a real 2-of-3 quorum ACCEPTED, not env-skipped) + peer-side
  `tests/tmultisig.nim` **4/4** (2-of-3 ACCEPTED; 1-of-3 / below-threshold M3 / non-local-quorum
  M6 REJECTED) — the keystone payoff on a rejection-heavy oracle category.
- **Type registry:** the 53-type §9.5 floor rendered **natively** from the peer's own
  TypeDef/FSpec model through its own ECF codec (not byte-ingest), byte-identical to
  `type-registry-vectors.diag`.
- **Origination-core:** `run-origination-core.sh` vs the Go `entity-peer` reference →
  **3/3 PASS** incl. §6.11 `dispatch_outbound_reentry` (live from the asyncdispatch single-loop
  `io.pending` request_id demux + the `OutboundSender` closure).
- **Codec floor:** S2 `wire-conformance` = **71/71** byte-identical (V8 corpus), first
  compile-run, 0 codec fixes; the mandatory `[2⁶³, 2⁶⁴−1]` head-form self-test passes at compile
  time and run time.

## Publish

`0.1.0-pre`. Nim's package registry is **nimble** — a git-indexed directory
(`packages.json` in `nim-lang/packages`), not a binary registry. "Publishing" = tag a git
release carrying this tree with a working `.nimble` and open a PR to the packages index (the
SWI-pack / Quicklisp-git model). A package need **not** be registered to be installed by git URL.
General nimble-registry submission is a later, review-gated community step — **deferred like the
whole cohort**. `[publishing] repository_url` is TBD on first publish. **Registry upload is an
operator decision after review; `/entity-rosetta` never publishes.**
