# entity-core-protocol-smalltalk — load & run (the Smalltalk "package")

Pharo/Smalltalk has **no binary package registry** — no PyPI/crates analogue. Distribution is a
**git repo + a Metacello baseline** (an optional Pharo-catalog listing is a listing, not a binary
store). A peer is a directory of **Tonel** `.st` package definitions loaded into a running image.
The distribution is therefore a **source tarball** (`make dist`) of the Tonel `src/` tree +
`tests/` + `bin/peer.st` + the run/conformance scripts + this stub + the `libentitycore_codec`
build recipe (a runtime dependency, documented, **not** bundled as a binary).

Pharo is a **live-image** system: "load" = file-in each Tonel package into a running `.image`,
in dependency order. There is no ahead-of-time compile step producing a binary. `load.st` is the
single source of truth for the load order (its `srcFiles` list); `make image` files it into a
fresh base image and snapshots a peer `.image` so the classes are compile-time visible to the
entry doit (the live-image single-doit constraint, A-ST-010).

## Dependencies

- **Pharo 13.0** (build.732, on the Linux-x86_64 stable VM) — the VM + base image. Bundles UFFI
  (the `ffiCall:module:` FFI wordset), SUnit, the `Socket` class, `Float asIEEE64BitWord`/
  `asIEEE32BitWord`, and arbitrary-precision integers. The `pharo-toolchain` container pins the
  image + VM by SHA-256 (`containers/pharo-toolchain/Containerfile`).
- **gcc / cmake** — to build the codec C-ABI recipe below (there is no compile step for the
  `.st`; it is filed-in / incrementally-compiled into the image).
- **`libentitycore_codec.so`** — the codec C-ABI (Ed25519/SHA over libsodium), built from
  `ffi-generator/c-abi/entity-core-codec-ffi-c` in the keystone repo (or any interchangeable
  `entity-core-codec-ffi-*` build). Build once with its CMake; the `.so` must be reachable at
  load time (UFFI dlopen's it by soname — see the env below).
- **libsodium** 1.0.18+ (the codec links it, statically + privately, into the `.so`).

## Build the codec floor (`make ffi`)

```
make ffi     # builds libentitycore_codec.so (its CMake, offline). The .so is built into
             # ../../ffi-generator/c-abi/entity-core-codec-ffi-c/build/ (its canonical dir).
             # UFFI warms the binding on the first crypto call (dlopen by soname).
```

UFFI dlopen's the codec `.so` by soname, so it must be on `LD_LIBRARY_PATH` at run time (the
Makefile's `FFI_ENV` sets this for every gate target):

```
export LD_LIBRARY_PATH=<codec>/build:$LD_LIBRARY_PATH   # dlopen at runtime
```

## Load the peer into an image (`make image`)

```
make image   # loads the Tonel src/ packages (per load.st) into a fresh base image and
             # snapshots ./entity-core.image (+ .changes / .sources). Depends on `make ffi`.
```

The live-image constraint (A-ST-010): a single doit compiles entirely before it runs, so it
cannot both install a class and reference it by global name in the same doit — hence the load +
snapshot step. The saved `.image` / `.changes` / `.sources` are **build artifacts** (gitignored,
regenerated by `make image`), not shipped in the tarball.

Once published, the idiomatic consumer load is the Metacello baseline (`repository_url` TBD on
first publish):

```smalltalk
Metacello new
    baseline: 'EntityCore';
    repository: 'github://<org>/entity-core-protocol-smalltalk:main/src';
    load.
```

## Run

**The peer** (networked host — the S4 CLI):

```
EC_PEER_PORT=7777 EC_PEER_NAME=mypeer [EC_PEER_VALIDATE=1] [EC_PEER_OPEN_GRANTS=1] \
  pharo --headless entity-core.image bin/peer.st
```

A headless `eval` appends extra argv tokens to the *source* (not to the doit's args, the A-ST bin
convention), so options travel via **environment variables**: `EC_PEER_PORT` (0 ⇒ ephemeral),
`EC_PEER_NAME` (loads the Ed25519 identity from `~/.entity/peers/NAME/keypair`, an entity-core PEM
= base64 of a raw 32-byte seed), `EC_PEER_SEED` (a single hex byte ×32 — a keypair-free test
convenience), `EC_PEER_VALIDATE=1` (the §7a `system/validate/*` conformance handlers, OFF by
default), `EC_PEER_OPEN_GRANTS=1` (the deprecated degenerate `default→*` seed policy, OFF by
default). It prints `LISTENING <port>` on stdout, then serves the single-event-loop (native BSD
Sockets + in-process UFFI crypto — no co-process daemon).

Keypair-free smoke (no `~/.entity` needed — the test convenience path):

```
EC_PEER_PORT=7825 EC_PEER_SEED=ab pharo --headless entity-core.image bin/peer.st   # → LISTENING 7825
```

(This is exactly the `make dist` verification: extract the tarball into a clean dir, build the
codec floor + peer image, and boot with `EC_PEER_SEED` → `LISTENING`.)

**Conformance / smoke** (reproduce the gates, container-bound + sealed-offline):

```
./run-s2.sh                 # codec corpus 69/69 + bignum uint64 boundary + crypto accept-path
./run-s3.sh                 # foundation self-test 25/25 + two-peer loopback smoke 6/6
./run-s4.sh                 # validate-peer --profile core (0 FAIL @ oracle cc1970f)
./run-origination-core.sh   # §10.2 dispatch_outbound_reentry (Go entity-peer as B)
```

## Publish

No binary registry step (none exists for Pharo). Publishing = tag a git release carrying this
tree + the tarball + the Metacello baseline; a Pharo-catalog listing is a later, review-gated
step. `0.1.0-pre` until the first tagged release. `/entity-rosetta` never publishes — this is an
operator decision after review.
