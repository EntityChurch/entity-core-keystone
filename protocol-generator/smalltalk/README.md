# entity-core-protocol-smalltalk

A **Pharo Smalltalk core protocol peer** for the Entity Core protocol (**v0.8.0 / V8**),
generated by the [`entity-core-keystone`](../../README.md) `/entity-rosetta` pipeline. The
cohort's **first pure-object / live-image / message-passing** peer (#26) — everything is an
object, all control flow is message-sends, and the program is a persisted memory *image*, not an
ahead-of-time-compiled source tree. It is an **FFI-hybrid**: **pure-Smalltalk canonical CBOR**
(the byte-floor's own encoder/decoder, expressed as a polymorphic `encodeOn:` double-dispatch
over tagged `Ec*` value objects), with crypto + SHA sourced over the codec C-ABI
(`libentitycore_codec`) through Pharo's **in-process** UFFI `ffiCall:module:` — a genuine libffi
call, **no subprocess / FIFO / co-process** (contrast Rexx's `ecnet` daemon), and **native BSD
sockets** in-process over the Pharo VM's SocketPlugin.

## What it is — the pure-object / live-image probe

Every prior peer keeps its state in named locals, typed records, tagged strings, or stack cells.
Smalltalk removes the procedure/keyword frame entirely: there are no free functions (every
operation is a *method* on an object), no control-flow keywords (`ifTrue:`, `whileTrue:`, `do:`,
`ifNil:` are *messages* to Boolean/Block/Collection), and no primitive values (an Integer, a
Character, a Boolean, a Class are all objects). The program is a live object graph in a persisted
`.image`, grown class-by-class, method-by-method. The probe question (A-ST-000) was **not**
"does the byte-floor express as Smalltalk?" (crypto legitimately doesn't — that's the C-ABI
floor's job) but "**can the recursive canonical-CBOR encoder + the §5 capability chain-walk be
expressed idiomatically as message-sends over an object graph — a value as a tagged `EcValue`
object, the codec as double-dispatch — or does the generator fall into procedural
'Smalltalk-flavored C' (a giant type-switch, primitive obsession)?**" — and the answer is
**corroboration**: the codec is a polymorphic `encodeOn:` per value class and the §5.5 chain
verifier reads as message-sends over `EcEntity`/`EcValue` objects, not a translated procedure.

Value on the current (saturated) wire surface is generator robustness, not a fresh spec finding
— and the S4 pass **is not vacuous**: the pure-object substrate flushed out real code bugs, each
caught by the oracle and fixed here (A-ST-014…017), chief the **A-ST-016 headline** (dispatch
caught only `EntityCoreError`, so one live `doesNotUnderstand:` on an unexercised path escaped
the frame and cascaded 229 FAILs from one bug — the resilience frame MUST be the language's
*root* error class on a no-static-check substrate) and the pure-object **A-ST-012** finding (a
distinguished-object absent sentinel is only safe if `isAbsent` is a polymorphic message on the
common `EcValue` supertype, else the "never nil-conflate absent" discipline still faults a DNU at
the first non-sentinel it meets). These, and the durable live-image toolchain lessons
(A-ST-010/011/013), are written up in [`status/SPEC-AMBIGUITY-LOG.md`](status/SPEC-AMBIGUITY-LOG.md)
and [`status/PHASE-S4.md`](status/PHASE-S4.md).

## The FFI-hybrid architecture (pure-Smalltalk codec + C-ABI crypto floor)

No platform CBOR library gives canonical ECF (shortest-float ladder + recursive major-type-6 tag
reject + length-then-lex key sort), so the peer hand-rolls it in Smalltalk; crypto (Ed25519,
SHA-256/384) is irreducibly the C-ABI's job (no audited native Ed25519 exists in the base image).
The split:

```
  ┌─────────────────────────────────────────────────────────────┐
  │  Pure-Smalltalk core  (src/EntityCore-{Codec,Peer,Capability})│
  │    EcCborEncoder/Decoder / EcVarint / EcBase58 / EcPeerId     │
  │       — §4 canonical ECF, a polymorphic encodeOn: over        │
  │         tagged EcValue objects (double dispatch);             │
  │       (f32/f64 assembled from NATIVE IEEE bits via            │
  │        Float asIEEE64BitWord/asIEEE32BitWord; only the f16    │
  │        leg + shortest-form ladder hand-rolled)                │
  │    EcCapability / EcCapAuthz — §5 chain walk + authz trichotomy│
  │    EcPeer / EcPeerHandlers — §6.5/§6.6 dispatch + §6.11 demux  │
  │    EcStore / EcEntity / EcEnvelope — §3.9 store, N4 fidelity   │
  │    EcNet — native BSD Sockets + single-event-loop serve pump   │
  └───────────────┬─────────────────────────────────────────────┘
                  │  src/EntityCore-Crypto/EcLibEntityCoreCodec.st
                  │      — in-process UFFI ffiCall:module:
                  ▼
  ┌─────────────────────────────────────────────────────────────┐
  │  C-ABI byte-floor  (libentitycore_codec, built from the      │
  │  ffi-generator/c-abi/entity-core-codec-ffi-c CMake)          │
  │    Ed25519 sign/verify/seed→pubkey, SHA-256 / SHA-384        │
  │    provenance via ec_impl_info(): c 0.1.0 / ecf-c-abi 1.1 /  │
  │    libsodium 1.0.22                                          │
  └─────────────────────────────────────────────────────────────┘
```

The C-ABI floor treats the entity `data` value as opaque pre-encoded bytes, so the peer **still
owns the data-value canonical CBOR** in pure Smalltalk; the 53/53 type-registry byte-diff proves
Smalltalk data-value canon matches the cross-impl encoder. Because Smalltalk integers are
**arbitrary-precision bignums** (`SmallInteger` promotes to `LargePositiveInteger`
transparently), the full uint64 range `[0, 2^64-1]` is carried FREE — the bignum class
(Rexx/Python/CL/Elixir/Haskell), with **no fixed-width `[2^63, 2^64-1]` head-form self-test tax**
(contrast Forth/Zig/C#/OCaml). The float tower is materially easier than Rexx's decimal-model
peer: Pharo's `Float asIEEE64BitWord`/`asIEEE32BitWord` yield real IEEE-754 bits, so only the f16
half-float leg + the shortest-form ladder are hand-rolled bit arithmetic.

### Run the peer

The live-image model (A-ST-010): the `EntityCore-*` classes must be compile-time visible to the
entry doit, so the peer runs against a **snapshotted peer image** (`make image` loads the Tonel
packages + snapshots), not the same `eval` that loads them. Then:

```sh
make ffi     # build libentitycore_codec (its CMake, offline)
make image   # load the Tonel packages into a fresh base image + snapshot entity-core.image
EC_PEER_PORT=7777 EC_PEER_NAME=mypeer [EC_PEER_VALIDATE=1] \
  pharo --headless entity-core.image bin/peer.st
```

A headless `eval` appends extra argv tokens to the *source* (the A-ST bin convention), so the
peer reads its options from **environment variables** (the run scripts export them):
`EC_PEER_PORT` (0 ⇒ ephemeral), `EC_PEER_NAME` (loads the Ed25519 identity from
`~/.entity/peers/NAME/keypair`, an entity-core PEM = base64 of a raw 32-byte seed), `EC_PEER_SEED`
(a single hex byte ×32 — a keypair-free test convenience), `EC_PEER_VALIDATE=1` (enables the
`system/validate/*` conformance handlers, OFF by default), `EC_PEER_OPEN_GRANTS=1` (the deprecated
degenerate `default→*` seed policy, OFF by default). On success the peer prints exactly
`LISTENING <bound-port>` on stdout, then serves the single-event-loop. `bin/peer.st` is the
conformance host driver — test/conformance tooling, not a frozen consumer surface.

## Distribution (`make dist` — a source tarball; no binary registry)

Pharo has **no binary package registry** — distribution is a git repo + a Metacello baseline (an
optional Pharo-catalog listing is a listing, not a binary store). So "the package" is a **source
tarball** (`make dist` → `dist/entity-core-protocol-smalltalk-0.1.0-pre.tar.gz`) of the Tonel
`src/` tree + `tests/` + `bin/peer.st` + the run/conformance scripts + `profile.toml` +
`status/` + `LICENSE` + this README + [`CHANGELOG.md`](CHANGELOG.md) + a
**[`LOAD.md`](LOAD.md)** load stub. This mirrors the COBOL / Rexx / Forth `make dist`
source-distribution convention (no registry inclusion step). The saved `.image` / `.changes` /
`.sources` are **build artifacts** (regenerated by `make image` — gitignored, not shipped);
`libentitycore_codec` is a **runtime dependency** documented (its CMake recipe), not bundled as a
binary — the tarball ships the recipe, the consumer builds the `.so`. **Verified:** `make dist` →
extract clean → build the codec floor + peer image → the packaged `bin/peer.st` boots to
`LISTENING`.

Publishing is an **operator step** (`/entity-rosetta` never publishes): tag a git release
carrying this tree + the tarball + the Metacello baseline; a Pharo-catalog listing is a later,
review-gated step. `repository_url` / `registry_url` are TBD on first publish — the same deferred
`0.1.0-pre` state as OCaml/Elixir/CL/Prolog/Tcl/Rexx/Forth.
