# entity-core-protocol-julia

A full **core-protocol** Entity Core peer in **Julia** (1.11.5). Generated by the keystone
`/entity-rosetta` pipeline as a **Tier-3 corroboration / generator-robustness peer** on a
fresh, native technical-computing substrate — its headline idiom axes are the
**multiple-dispatch codec** (encode/decode dispatched on the Julia value *type*, the
CLOS/Smalltalk double-dispatch family) and the **UInt64 + BigInt hybrid numeric model**.

**Conformance:** `validate-peer --profile core` → **682 · 0F @ `cc1970f`**
(292 P / 294 W / 0 F / 96 S) — `Result: PASS`.
See [`status/CONFORMANCE-REPORT.md`](status/CONFORMANCE-REPORT.md) for the full
per-category table and [`status/CONFORMANCE-REPORT.json`](status/CONFORMANCE-REPORT.json)
for the machine record. Tracks **ENTITY-CORE-PROTOCOL v0.8.0 (V8)**.

> **Honest framing (ADR-0012).** Julia shares the generation lineage of the keystone
> cohort — a Julia peer passing the author's vectors is **cohort-consistent corroboration,
> not independent convergence**. The alien-substrate spec-discovery well is dry on the
> current wire surface; this peer's value is (a) corroborating the settled cohort results

## What this peer is (the idiom axes)

Julia's rich type system makes CBOR major-type selection **natural** — the opposite of the
Tcl EIAS problem. `encode`/`decode` are generic functions dispatched by **multiple
dispatch** on the value type: `String`→mt3, `Vector{UInt8}`→mt2, `Integer`→mt0/1,
`AbstractFloat`→mt7. Byte-vs-text and int-vs-float are **type-distinguished**, never
inferred — corroborating that the spec's type distinctions are carriable by a dispatch-typed
value model with no side channel (confirmed at S2: no value satisfies two dispatch branches,
A-JULIA-006).

The **numeric model is a hybrid** on the head-form axis: native `UInt64` exactly covers the
CBOR uint64 argument tower `[0, 2⁶⁴−1]` (no signed-carrier trap like Fortran, no unsigned
gap), while `BigInt` (GMP) carries any *reconstructed application value* overflow-free.
Because the wire carrier is **fixed-width** (`UInt64`), the mandatory `[2⁶³, 2⁶⁴−1]`
head-form self-test applies (the C# `ulong` / Zig `u64` class) even though BigInt makes
application-level full range free — it passes byte-exact (A-JULIA-008).

`Float64`/`Float32`/`Float16` are all **native IEEE-754** Julia types
(`reinterpret(UInt64/UInt32/UInt16, x)` bit path, explicit big-endian byte-swap); only the
shortest-float ladder decision (does the value round-trip through f16/f32 exactly?) is
hand-rolled, per Rule 4.

## Codec & crypto floor (native — no C-ABI)

Unlike the FFI-hybrid alien-substrate probes, Julia's floor is **fully native** — the
shipped default peer needs **no `libentitycore_codec`**:

- **CBOR value codec — pure Julia** (`src/cbor.jl`): hand-rolled canonical ECF encoder /
  decoder, multiple-dispatch on the value type. No Julia CBOR package gives canonical ECF
  (CBOR.jl offers none of the shortest-float / length-then-lex key order / mt6-tag-reject /
  byte-string-fidelity guarantees, so it is declined — A-JULIA-002); hand-rolling is both
  the faithful and the simpler path.
- **SHA-256 / SHA-384 — Julia `SHA` stdlib** (ships with Julia; `SHA.sha256` /
  `SHA.sha2_384`). No supply-chain cost.
- **Ed25519 — system libsodium via `ccall`** (`src/sign.jl`): Julia's first-class C interop
  binds `crypto_sign_seed_keypair` / `crypto_sign_detached` / `crypto_sign_verify_detached`
  directly. This is the **native-audited-lib crypto tier** (the Elixir OTP `:crypto` /
  Haskell crypton class) — **NOT** the keystone C-ABI FFI-hybrid. libsodium is present in the
  toolchain image; binding it by `ccall` keeps the peer self-contained + Pkg-fetch-free
  (Sodium.jl is declined for the network-fetch + thin-need reasons, A-JULIA-003).
- **base58 + multikey varint — pure Julia** (`src/base58.jl`, `src/varint.jl`): BigInt makes
  base-256↔base-58 long division trivial; the LEB128 varint is inline bit ops.

**Crypto floor:** Ed25519 + SHA-256 (native / system-libsodium). **Ed448 + SHA-384 agility
is deferred** — libsodium has no Ed448, so the agility family is an opt-in hybrid-FFI
sub-package over the C-ABI (`ec_ed448_*`), scoped so the shipped Ed25519+SHA floor peer stays
native + self-contained (A-JULIA-004). Wire it when an adopter needs agility.

## Concurrency (§7b, structural)

The core peer runs Julia's **single-threaded Task scheduler** (cooperative coroutines /
green threads over the libuv reactor). §7b store-safety is therefore **structural** — the
store is plain Julia `Dict`s mutated only between yield points on the one scheduler thread,
so there is no data race to guard (no lock, no atomics) — the actor/CSP-class "free
store-safety" reached via a cooperative event loop (the PHP/Dart/Tcl result on a fourth
substrate). §6.11 handler-initiated outbound-dispatch reentry is a plain `Channel` handoff
keyed by `request_id` — no cross-thread demux, no correlation-map tax.

## Build

Container-bound (Podman, `julia-toolchain:latest`, `fedora:43` base, sealed-offline). The
core peer pulls **zero registered packages** — `SHA` / `Sockets` / `Test` / `Pkg` are Julia
stdlibs bundled with the toolchain, and Ed25519 is system libsodium via `ccall` — so it
loads + precompiles fully **offline** (`--network=none`) once the image exists.

```
. tools/podman-caps.sh   # from the keystone repo root — sets $PODMAN_RUN_CAPS

./run-conformance.sh     # S2 codec gate: v0.8.0 ECF corpus 71/71 byte-identical
./run-conformance.sh --tests   # full Test-stdlib suite (self-tests + corpus)
./run-s3.sh              # S3 peer machinery: two-peer loopback handshake + demux smoke
./run-s4.sh              # S4 live-peer validate-peer --profile core (0 FAIL @ cc1970f)
```

> **Offline test invocation (A-JULIA-009).** The gates use `julia --project=. test/<file>.jl`
> directly, **not** `Pkg.test()` — `Pkg.test()` git-clones the General registry
> (`download_default_registries`) even for a stdlib-only package with zero registered deps,
> which fails under the (correct) `--network=none` build. `using EntityCore` + the stdlib
> deps resolve fully offline from `Project.toml` alone. `Pkg.test()` is the *registered /
> online* form recorded in `profile.toml`; the direct-file form is the offline-correct gate.

"Build" for a JIT language is load + precompile:

```
julia --project=. -e 'using Pkg; Pkg.precompile(); using EntityCore; println("ok")'
```

## Run

```
julia --project=. bin/peer.jl --name NAME [--port N] [--validate]
```

Loads the peer's Ed25519 identity from `~/.entity/peers/NAME/keypair` (entity-core PEM =
base64 of a 32-byte seed), binds the port (`0` = ephemeral), prints a single
`LISTENING 127.0.0.1:PORT` readiness line, then runs the single-threaded Task scheduler.

- **`--name NAME`** — persistent identity + peer-manager interop (the cohort convention).
  The keypair must exist at `~/.entity/peers/NAME/keypair` (the conformance harness
  provisions it; the peer does not auto-create it).
- **`--port N`** — listen port (`0`/omitted = ephemeral).
- **`--validate`** — bootstrap the §7a `system/validate/*` conformance handlers (incl. the
  §6.11 `dispatch-outbound` reentry). **OFF by default** — a standing outbound originator
  must not ship in production.
- **`--debug-open-grants`** — degenerate `default→*` seed policy. Deprecated (§6.9a); debug
  only, non-conformant.

**No runtime C-ABI dependency** for the floor peer. `libentitycore_codec` is needed **only**
by the opt-in Ed448 agility sub-package (`src/ffi_ed448.jl`), which the floor peer never
loads.

## Publish

`0.1.0-pre`. Julia's package registry is the **General registry** (`Pkg`), keyed by the
per-package UUID in `Project.toml`; registration is a PR to the registry via
Registrator/JuliaHub. A package need **not** be registered to be `Pkg.add`ed by URL. Publish
= tag a git release carrying this tree with a working `Project.toml`; General-registry
registration is a later, review-gated community step — **deferred like the whole cohort**.
`[publishing] repository_url` is TBD on first publish. **Registry upload is an operator
decision after review; `/entity-rosetta` never publishes.**
