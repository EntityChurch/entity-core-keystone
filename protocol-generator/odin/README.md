## Honest framing (ADR-0012)

This is a **corroboration / generator-robustness** peer, **not** spec-discovery. The
alien-substrate discovery sweep is closed — the well is dry on the current wire surface (the
discovery axes crypto-availability / integer-model / memory-model / string-model are saturated
across the cohort). A green verdict here is **cohort-consistent, not independent
convergence**: the `validate-peer` oracle and the type-registry vectors are the Go author's
artifacts, so one peer passing one author's vectors is generator robustness on a fresh shape —
not a second independent witness to the protocol bytes. What Odin adds is a value-return error
idiom, a no-package-manager packaging path, no-GC context allocators, and a native pure-Odin
crypto re-derivation of the same Ed25519/SHA bytes.

## The idiom — data-oriented systems, no GC, no exceptions

Odin is fixed-width-int, manually-memory-managed, and exception-free by design. The seams the
generator exercised on this substrate:

- **Native pure-Odin crypto floor.** Ed25519 sign/verify/keygen (`core:crypto/ed25519`, RFC
  8032 / FIPS 186-5) and SHA-256/384/512 (`core:crypto/sha2`) are source-verified pure Odin
  (no `foreign import`) — the whole crypto floor is native + FFI-free (the native-pure-lang
  tier, Dart / Common Lisp precedent). Gated beyond the 3 corpus signature vectors by two
  independent KATs (the corpus all-zero-seed signature + RFC 8032 §7.1 vector 1), so the
  unaudited-crypto caveat (A-ODIN-004: `core:crypto` self-declares "not received independent
  third-party review") is **oracle-gated, not asserted** — any RFC-8032 deviation fails loudly.
- **Hand-rolled canonical CBOR.** No platform CBOR library gives canonical ECF. Odin's stdlib
  `core:encoding/cbor` is canonical-*aware* (f16→f32→f64 float ladder + deterministic int/float
  modes) but its map sort is pure bytewise (not ECF's length-then-lexicographic) and it has no
  decode-side major-type-6 tag reject — so the codec is hand-rolled regardless (the A-005
  pattern, 29th time), with `core:encoding/cbor` kept only as a float-ladder cross-check.
- **No-GC `context` allocators.** No garbage collector — allocation flows through
  `context.allocator` (+ `context.temp_allocator` for per-request scratch); decode returns
  owned data with a documented `defer`-free contract. Free-correctness is a first-class
  conformance concern: the whole test + smoke suite runs under `mem.Tracking_Allocator` and
  fails on any un-freed allocation or bad free.
- **No exceptions — value-return errors.** The fallible surface is multi-return with a trailing
  `Codec_Error` enum value (`.None` = success), propagated with `or_return` and defaulted with
  `or_else`; panic is reserved for true unreachable / programmer error. Distinct from Zig's
  language-level `!T` error union — here it is a plain value enum.
- **Raw OS threads + `sync.Mutex` (§4.8 store-safety).** No actor/CSP/STM substrate — raw
  `core:thread` OS threads with `core:sync` primitives. Store-safety is enforced **manually**
  (an explicit `sync.Mutex` around the §4.8 store + §3.9 CAS), one reader thread per connection,
  each inbound EXECUTE dispatched on its own thread; the §6.11 handler-outbound demux is a
  `{request_id → waiter}` + `sync.Cond` correlation-map tax (not free, as the raw-thread class
  is). TCP_NODELAY on every socket.
- **No package manager → git-vendored.** Odin has no central registry (no cargo/npm/crates
  analogue). Consumers vendor the package (Ginger Bill prefers git subtree); "publish" = a git
  tag. `make dist` (below) produces a source tarball.

## What was built (package `entity_core`, `src/*.odin`)

## Build / test / run (in-container, offline)

All build, test, and conformance runs happen inside the pinned `odin-toolchain` Podman image
(`fedora:43` base + stock Fedora LLVM/clang + the Odin compiler built from source at
`dev-2026-06:285f6d8`). The core peer pulls **zero** third-party packages (`core:crypto` +
`core:` covers crypto / hashing / threads / testing / cbor-survey), so every run is sealed
offline (`--network=none`). There is **no host Odin dependency**. Cap every `podman run` per
[`RESOURCE-CAPS.md`](../../RESOURCE-CAPS.md) (`. tools/podman-caps.sh` → `$PODMAN_RUN_CAPS`).

```sh
# Build the peer host (odin compiler is the build system; a package is a directory of .odin)
make build            #  → odin build host -out:bin/entity-core-peer

# S2 — codec + peer unit suite: 71/71 corpus + u64 [2^63,2^64-1] head-form + Ed25519 KATs +
#      the peer accept-path units, all leak-checked under mem.Tracking_Allocator
make test             #  → odin test test    (also: ./run-s2.sh)

# S4 — live-peer conformance (validate-peer --profile core, 0 FAIL). The Odin peer + the Go
#      oracle ELF run together in the image over one loopback, --network=none.
. tools/podman-caps.sh
podman run $PODMAN_RUN_CAPS --rm --network=none -v "$PWD":/work:Z \
  entity-core-keystone/odin-toolchain:latest \
  sh /work/protocol-generator/odin/run-s4.sh -profile core \
     -json-out /work/protocol-generator/odin/status/CONFORMANCE-REPORT.json
```

The S4 oracle (`output/s4-oracles/validate-peer`) is a `CGO_ENABLED=0` Go ELF built from
`entity-core-go @cc1970f`; it is vendored gitignored and rebuilt per
[`status/CONFORMANCE-REPORT.md`](status/CONFORMANCE-REPORT.md). Origination-core probes are
reference-peer-gated; a single-peer `run-s4` honest-SKIPs them.

### Run the peer

```sh
odin build host -out:bin/entity-core-peer -o:speed
bin/entity-core-peer --port N --name NAME [--validate] [--debug-open-grants]
```

`--name NAME` loads the Ed25519 identity from `~/.entity/peers/NAME/keypair` (entity-core PEM =
base64 of a raw 32-byte seed) — persistent identity + peer-manager interop. `--validate` enables
the `system/validate/*` conformance handlers (**off by default** in production; `run-s4.sh`
turns it on for the §7a probes). `--debug-open-grants` is the deprecated degenerate `default→*`
seed policy. On success the peer prints exactly `LISTENING <bound-port>` on stdout, then serves.
`bin/entity-core-peer` is the conformance host driver — test/conformance tooling, not a frozen
consumer surface.

## Distribution (`make dist` — a source tarball; no Odin registry)

Odin has **no package manager** — consumers vendor the package (git subtree / tag pin). So
"the package" is a **source tarball**: `make dist` →
`dist/entity-core-protocol-odin-0.1.0-pre.tar.gz` of the `src/*.odin` tree + `host/` + `smoke/`
+ `test/` + `status/` + `arch/` + the run scripts + `profile.toml` + `README` + `CHANGELOG` +
`LICENSE`. **No compiled binaries** ship — the consumer builds with their pinned Odin toolchain.
This mirrors the Forth / COBOL / Rexx `make dist` source-distribution convention (no registry
inclusion step).

Publishing is an **operator step** (`/entity-rosetta` never publishes): tag a git release
carrying this tree + the tarball; an Odin-community listing is a later, review-gated step.
`repository_url` / `registry_url` are TBD on first publish — the same deferred `0.1.0-pre` state
as the OCaml / Elixir / CL / Forth / Rexx peers.

## Known limitations / honest notes

- **Ed448 / crypto-agility higher bar deferred** (cohort-wide). `core:crypto` has no Ed448
  signature scheme (only x448 ECDH — verified absent). The documented future path is hybrid-FFI
  via `libentitycore_codec` (`ec_ed448_*`) bound with Odin's `foreign import` as an **opt-in
  sub-package**, so the shipped default peer stays self-contained (core:crypto-only, FFI-free).
  Does not affect the Ed25519/ECF conformance floor. See
  [`status/SPEC-AMBIGUITY-LOG.md`](status/SPEC-AMBIGUITY-LOG.md) A-ODIN-002.
- **The native crypto floor is unaudited by design** (A-ODIN-004): `core:crypto` self-declares
  no independent third-party review and assumes 64-bit. This is an operator note, not a floor
  blocker — the KAT accept-path + the oracle gate the actual bytes. A libsodium-via-`foreign
  import` fallback is a drop-in if an operator requires an audited floor.
- The compiled binaries (`bin/entity-core-peer`, `bin/smoke`) and the vendored oracle ELFs
  (`output/s4-oracles/`) are gitignored build outputs — sources + run scripts are committed.
- No package registry / no version-grammar field to carry `0.1.0-pre` (see
  [`CHANGELOG.md`](CHANGELOG.md)).
