# PHASE-S3 — entity-core-protocol-asm-x86_64 (in progress)

The live-peer machinery, hand-authored in x86-64 assembly (GAS/AT&T). Codec/crypto/peer-id
are FFI (`libentitycore_codec`); transport + the envelope/data-map CBOR + dispatch are asm.

## Working + oracle-validated

- **Boot + identity** (committed `169bb3a`). CLI parse, PEM keypair read (openat/read),
  hand-rolled base64 decode → 32-byte seed → FFI pubkey → FFI base58 peer_id. The derived
  peer_id for the 0x11×32 seed is **byte-exact** vs the reference Go `entity-peer`
  (`2KHoAk7A5JmhygZJAdBua8iRD1CnBoJRfUBHgZeXNRTeFg`). socket/bind/listen + `TCP_NODELAY`;
  the `LISTENING` line in run-s4.sh's exact shape.
- **hello handshake** (committed `8c118fd`). Against `validate-peer -category connectivity`
  (direct): **PASS** `tcp_connect`, `hello_response_format`, `hello_nonce_present`,
  `hello_peerid_valid`, `hello_protocols_present`. The hello EXECUTE_RESPONSE is built
  bottom-up in asm (inner hello entity → `ec_content_hash` → response entity →
  `ec_content_hash` → envelope → 4-byte BE frame) and is byte-structurally identical to the
  reference peer's.
- **CBOR map layer** (`cbor.s`): canonical reader (`read_head`/`skip_value`/`map_find`/
  `get_text`) + writer (cursor-in-`r15` emitters). This is the A-ASM-004 surface the FFI
  doesn't cover.
- **Transport concurrency**: fork-per-connection (A-ASM-003/005). Removes the head-of-line
  blocking that a single-threaded blocking accept loop hits under validate-peer's
  concurrent/lingering connections. Unblocks the **stateless** categories.

### §5.2 get-path verification (this session) — the four stages that gate `serve_tree_get`
- **Auth-class (401)** — `verify_get_auth`: request must carry an `author` whose `system/peer`
  is in `included` (→ pubkey), and `included` must hold a `system/signature` (signer=author,
  target=root.content_hash) that Ed25519-verifies.
- **Capability-class (403)** — `verify_get_cap`: `capability` token in `included`,
  `grantee`==author, validly signed by its `granter` (granter peer + Ed25519 sig over the
  token hash). Also fixed the malformed-token multisig rejections.
- **Grant-scope (403 default-deny)** — `verify_get_scope` + `grant_scope_ok`: a grant in
  `token.grants[]` must permit (operation, `system/tree` handler, resource-target), with
  `*` and trailing-`/*` wildcards (`array_contains_star`, `resource_matches`).
- **Temporal (403)** — `expires_at`/`not_before` window checked against wall-clock ms.
- **Content-hash + root-trust (403)** — recompute `ec_content_hash(token type, data)` vs the
  presented `included` key (rejects post-signing substitution); require `token.granter` ==
  this peer's `identity_hash` (we mint every token at authenticate, so a forged root or a
  delegated child — granter ≠ us — fails closed until a chain-walk exists).
- **Unrouted-op scope** — the 501 catch-all first runs `verify_get_scope`, so an operation a
  capability doesn't cover returns 403 rather than 501.
- Valid requests (the type_system cohort) carry proper auth, self-consistent server-granted
  unexpiring tokens whose grant matches `system/type/*`, so every stage passes them untouched
  — the 400-check green is preserved throughout. New readers: `included_find_by_key`,
  `find_req_sig`, `array_contains_star`, `resource_matches`.

Landed this session:
- **`system/tree` get over an embedded read-only store** — `serve_tree_get` resolves
  `resource.targets[0]` against `type_table` (`src/typestore.s`, generated by
  `tools/gen-typestore.py`), returns the stored entity verbatim as the `result` of a 200
  EXECUTE_RESPONSE (`send_get_ok`), else 404. **type_system 400/400** and the static
  **handlers** interface checks (`handler_{connect,tree,capability}_*`,
  `handlers_listing_available` = 16) now pass. See A-ASM-006.
- **Byte-exact bootstrap harvest** — 199 type entities + 4 `system/handler/*` entities
  captured from the reference peer through the now-concurrent `tools/teeproxy.c` and
  embedded in `.rodata` (shared across fork workers for free).
- **`encoding.ecf_key_ordering`** — the `included` map is now emitted sorted by 33-byte key
  (`emit_sorted_included` + `mcmp33`); fixed a data-dependent 32-bit-sign sort bug
  (A-ASM-009) that made the failure intermittent.
- **`negotiation`** — hello now rejects disjoint `hash_formats`/`key_types` with 400
  (`check_hello_negotiation` + `array_contains`).
- **No-silent-drop catch-all** — unknown operations return `501 not_implemented` instead of
  hanging validate-peer ~20 s/probe (A-ASM-007); the full sweep now completes in ~350 ms.

## Remaining `--profile core` gates (12 fails)

| Category | Fail | What it needs |
|---|---|---|
| handlers (`core_register_*`) | 9 | `register`/`unregister` + tree `put` **write** ops → an in-process store (see A-ASM-011: per-fork `.bss` suffices for the core gate — NOT the MAP_SHARED/epoll refit) |
| peer_canonicalization | 2 | `peer_pattern_1/2` — canonical-form cap-pattern match + lazy-canon mint (`configure` write) |
| multisig | 1 | `valid_2of3_peer_signed_accepted` — K-of-N accept with full M3 validation (A-ASM-012) |

**Next pieces, in rough order:**
1. **In-process write store** (A-ASM-011, re-scoped from A-ASM-003) — a per-fork `.bss` append
   store: `put` writes `path→entity`, `get` reads it before the `.rodata` typestore,
   `register`/`unregister` store/remove handler entities. `--profile core` multiplexes the
   stateful probes onto one connection served by one fork, so per-fork state persists across
   frames — **no MAP_SHARED/epoll needed for the core gate**. Unblocks handlers (9) +
   peer_canonicalization's `configure` (2). This is the bulk of the remaining 12.
2. **Multisig accept** (A-ASM-012) — impose the full §3.6 M3 rules (threshold ≥ 2,
   2 ≤ threshold ≤ N, N ≥ 2, distinct signers, null parent, local ∈ signers) then count
   ≥ threshold valid signatures; the 10 reject probes are the regression harness.
3. **Delegation-chain walk** (still open) — replace the fail-closed root-trust check with a
   real `parent` walk so *valid* delegations are accepted (chain rejects already pass closed).

The read-only serving layer, the full get-path §5.2 verification, the `request` mint, and the
dispatch-level authz codes needed no store; the remaining write ops are the last grind.

### The last two — §7a reentry — were NOT architecturally out of reach (correcting A-ASM-013)

An earlier draft called `t1_2_concurrent_reentry` impossible for a blocking fork peer. That was
wrong, and the fix proves it:

8. **§7a validate scaffold + dispatch-outbound reentry** — publish the
   `system/handler/system/validate/{echo,dispatch-outbound}` interfaces (`seed_vh`); getting
   `system/handler/system/validate/dispatch-outbound` to 200 is the oracle's **`--validate`
   gate** (our peer 404'd it, so both §7a checks skipped). `validate_echo_dispatch` then passes
   on our existing verbatim `echo`. For `t1_2`, `serve_dispatch_outbound` **originates** a signed
   reentry echo EXECUTE (5-entry sorted `included`: our peer + PoP sig + the handed-in
   `reentry_capability`/`_granter`/`_cap_signature`) to the target peer — which is the validator
   **on the same connection** — and `handle_dispatch_response` demuxes the reply by `request_id`
   (`pending_tab`) back to its dispatch. `conn_serve`/`dispatch` route by root type
   (`…/execute/response` → response path). **A single-threaded blocking fork handles all 8
   pipelined dispatches + their demuxed replies with a pending table — no threads, no epoll.**
   The reentry is one socket (validator-as-B); the "needs an async refit" claim was mistaken.

Everything a `--profile core` peer must do on the wire — read and write ops, the full authority
interior, multisig, revoke, handler normalization, and bidirectional reentrant dispatch — is
implemented in hand-written x86-64 assembly (codec/crypto via `libentitycore_codec`).
