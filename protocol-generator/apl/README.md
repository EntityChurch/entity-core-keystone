# entity-core-protocol-apl

A full **core-protocol** Entity Core peer in **APL** (GNU APL 1.9, ISO/IEC 13751 Extended
APL). Generated by the keystone `/entity-rosetta` pipeline as the cohort's **array /
value-model alien-substrate probe** — the array-as-primitive-value expression of the
"integer head-form is a fixed-width artifact, not a protocol property" lesson.

**Conformance:** `validate-peer --profile core` → **682 · 0F @ `cc1970f`**
(291 P / 295 W / 0 F / 96 S) — `Result: PASS`.
See [`status/CONFORMANCE-REPORT.md`](status/CONFORMANCE-REPORT.md) for the full
per-category table and [`status/CONFORMANCE-REPORT.json`](status/CONFORMANCE-REPORT.json)
for the machine record. Tracks **ENTITY-CORE-PROTOCOL v0.8.0 (V8)**.

> This is a **keystone-generated** peer sharing the generation lineage of the cohort —
> **cohort-consistent, not independent convergence** ([ADR-0012]). The oracle is ground
> truth; every S4 FAIL was a *peer* bug fixed from the spec, never an oracle relaxation.

> Scope: **core Layers 0–4** (substrate, identity, interaction, capability, bootstrap).
> No standard extension (TREE, CONTENT, IDENTITY, ATTESTATION, QUORUM, REGISTRY, RELAY) is
> implemented — the extension surface stops at the dispatcher interface. This is a
> *provided* conformance peer, not a mandate; anyone may build a ground-up implementation.

## What this peer is (the probe)

APL's paradigm is the **array-as-primitive-value**: there is no scalar/collection
distinction, every value is an array, and the natural codec is base-conversion + grade over
vectors (`⊤ ⊥ ⍋ ⍒ ⌽`). The experimental question: does a from-spec canonical-CBOR codec fall
out of array primitives as cleanly as it does from scalar bit-ops, and does the generator
survive a language with **no statement-level control flow** in its pure-function (dfn) form?
The bet was **corroboration + generator-stress**, not a fresh wire finding — the
spec-discovery well is dry on the current wire surface (AGENTS.md durable lesson), and this
run confirms that prediction: **zero fresh wire findings**, a durable crop of GNU-APL
array-idiom lessons.

The one genuinely wire-touching axis is the numeric ceiling, and here APL is **sharper than
Fortran**. GNU APL's exact integer is signed `int64` (ceiling `2⁶³−1`); at/above `2⁶³` it
**silently promotes to IEEE double** — precision lost above `2⁵³`, with **no error raised**
(verified in-container: `2*62` prints exact, `(2*63)-1` prints `9.223372037E18` in float
form). Fortran's signed `int64` at least holds the 64-bit pattern in a carrier you fully
control; **APL's overflow *escapes* to a lossy float**. So the ECF `uint64` tower
`[2⁶³, 2⁶⁴−1]` cannot be a native APL scalar *at all*. The carrier is therefore the **array
itself**: the high range lives as an 8-element big-endian **octet vector** (int64 cells
`0..255`), built and consumed by array base-256 arithmetic that never forms the `>2⁶³` scalar
(never `256⊥`'d — [`A-APL-002`](status/SPEC-AMBIGUITY-LOG.md)/`A-APL-003`). A mandatory
self-test round-trips every value in `{0, 2⁶³−1, 2⁶³, 2⁶⁴−2, 2⁶⁴−1}` byte-exact. This is the
fixed-width-artifact lesson expressed in the array model.

Floats: APL's float is native IEEE `binary64`, but APL has **no bit-reinterpret primitive**
(no `transfer`, no bits-of-float) — so f64/f32 IEEE bit access is hand-rolled arithmetic
decomposition (sign / biased-exp / mantissa via `⌊` and `×÷` powers of two, the Rexx-family
float path); f16 and the shortest-float ladder (Rule 4) are hand-rolled regardless
([`A-APL-005`](status/SPEC-AMBIGUITY-LOG.md)).

## Codec & crypto floor (FFI-hybrid)

- **CBOR value codec — pure APL** (`src/cbor.apl`): the array-model probe. No APL CBOR
  package gives canonical ECF, so the encoder/decoder is hand-rolled over `⊤`/`⊥` base-256,
  `⍋` grade (length-then-lex map-key ordering as a permutation), and `⌽ ↑ ↓ ⍴ , ⊂ ⊃` for
  buffer assembly. The value model is a **nested array with an explicit integer major-type
  discriminant cell** — APL arrays do not carry the CBOR major type, so int-vs-float and
  byte-vs-text intent are explicit, never inferred from APL storage
  ([`A-APL-011`](status/SPEC-AMBIGUITY-LOG.md)).
- **Crypto / entity-framing / base58 — the C-ABI** (`libentitycore_codec`, C-ABI **1.1**):
  no native audited APL crypto exists, so the §9.1 signature floor is an FFI obligation from
  the start. The binding is a **GNU APL native function** (`soname ⎕FX funname`): a C++ shim
  (`src/ext/ec_native.cc → ec_native.so`) wraps `ec_ed25519_{seed_to_pubkey,sign,verify}`,
  `ec_sha256/384`, `ec_encode_ecf` / `ec_content_hash` (entity framing), `ec_decode_entity`,
  and `ec_peerid_{parse,format}` (base58 — APL has no exact bignum past `2⁶³`, so the
  base-256→base-58 long-division rides the C-ABI, [`A-APL-010`](status/SPEC-AMBIGUITY-LOG.md)).
  `apl` is linked `-export-dynamic` so the dlopen'd shim resolves apl's own symbols at `⎕FX`
  load.
- **Transport is native `⎕FIO`** — a point of difference from COBOL/Fortran. GNU APL ships
  Berkeley sockets in its `⎕FIO` file-I/O family (`⎕FIO[32]` socket, `[34]` listen, `[35]`
  accept, `[36]` connect, `[37]` recv, `[38/39]` send, `[40]` select), so there is **no C
  net-shim** ([`A-APL-006`](status/SPEC-AMBIGUITY-LOG.md)). The byte-per-cell recv/send
  matches the array byte model exactly. The peer is a single-threaded select-pump; §7b
  store-safety is **structural** (one image, one thread, no lock, no race); the §6.11
  handler-outbound reentry is a manual, serialized correlation-map pump
  ([`A-APL-017`](status/SPEC-AMBIGUITY-LOG.md)).

**Crypto floor:** Ed25519 + SHA-256 (via `libentitycore_codec` / libsodium). **Ed448 /
SHA-384 agility is deferred** (opt-in, via the C-ABI `ec_ed448_*` / `ec_sha384` when an
adopter scopes it — there is no native APL Ed448).

## Build

Container-bound (Podman, `fedora:43` base, sealed-offline). The interpreter itself is
**GNU APL 1.9 built from the SHA-256-pinned GNU source tarball** — it is **not in the
fedora:43 dnf repos** (verified: `dnf list apl / gnu-apl` empty; no APL-family interpreter
is packaged — [`A-APL-001`](status/SPEC-AMBIGUITY-LOG.md)/`A-APL-004`), so the
`apl-toolchain` image configures + builds it from source (autotools, GCC 15, `readline`).
apl-2.0 (2026-06-24) was **declined** — only ~18 days old at authoring, violating the S11
30-day supply-chain floor.

APL is **interpreted** — there is no compile step for the `.apl` source. The **only** compiled
artifact is the native-function C++ shim, built against apl's **retained source-tree headers**
(`make install` ships only `libapl.h`, so the image keeps `/opt/apl-1.9` —
[`A-APL-009`](status/SPEC-AMBIGUITY-LOG.md)).

```
make shim          # build libentitycore_codec (CMake) + compile src/ext/ec_native.cc -> ec_native.so
make test          # S2 codec gate: pinned v0.8.0 corpus 69/69 + unit suite (ALL PASS)
make s3            # S3 peer gate: offline self-test 18/18 + two-peer loopback smoke 5/5
make dist          # source tarball -> dist/entity-core-protocol-apl-0.1.0-pre.tar.gz
```

The reproducible container gates (self-re-exec under capped Podman, `--network=none`):

```
./run-s2.sh        # codec corpus 69/69 (byte-identical)
./run-s3.sh        # peer machinery (self-test + loopback smoke)
./run-s4.sh        # validate-peer --profile core  (0 FAIL @ oracle cc1970f)
```

## Run

The peer is launched by loading the workspace modules into `apl` and entering the `⎕FIO`
dispatch loop:

```
apl --script <S3 modules> -f bin/peer.apl -- --name NAME [--port N] [--validate]
```

(the module load order is the Makefile's `S3MODS`; `run-s3.sh` / `run-s4.sh` assemble it for
you). The peer loads its Ed25519 identity from `~/.entity/peers/NAME/keypair` (entity-core PEM
= base64 of a 32-byte seed; created if absent), binds the port (`0` = ephemeral), prints a
`LISTENING <port>` readiness line, then runs the single-threaded select-pump.

- **`--name NAME`** — persistent identity + peer-manager interop (the cohort convention).
- **`--validate`** — bootstrap the §7a `system/validate/*` conformance handlers (incl. the
  §6.13(b) `dispatch-outbound` reentry). **OFF by default** — a standing outbound originator
  must not ship in production.
- **`--debug-open-grants`** — degenerate `default→*` seed policy. Deprecated (§6.9a); debug
  only, non-conformant.

**Output must be file-redirected, never piped** — GNU APL 1.9 does not terminate at `)OFF`
when its stdout is a pipe ([`A-APL-013`](status/SPEC-AMBIGUITY-LOG.md)); the run scripts
redirect to a file and scrape the `LISTENING` line.

**Runtime dependency:** `libentitycore_codec.{so}` (the codec C-ABI, from
`ffi-generator/c-abi/entity-core-codec-ffi-c` in the keystone repo, or any interchangeable
`entity-core-codec-ffi-*` build). Build once with its CMake; point `LD_LIBRARY_PATH` at the
resulting `build/` dir (the shim also carries an `-Wl,-rpath` to it).

## Publish

`0.1.0-pre`. APL has **no mature package registry** — Dyalog's Tatin is Dyalog-ecosystem
specific; GNU APL workspaces are distributed as `.apl` source files. Publish = tag a git
release carrying this tree + the `make dist` source tarball (the `.apl` workspace + the
`ec_native.cc` shim source + the build recipe). Registry inclusion is not applicable; a git
tag is the deliverable. `[publishing] repository_url` is TBD on first publish. **Registry
upload / tagging is an operator decision after review; `/entity-rosetta` never publishes** —
this is the deferred `0.1.0-pre` state shared by the whole cohort.

**License note ([`A-APL-008`](status/SPEC-AMBIGUITY-LOG.md)) — read before shipping a binary.**
The `.apl` peer source is *interpreted* by apl (no linking) → no license entanglement. But the
native-function shim (`src/ext/ec_native.cc`) `#include`s GNU APL's **GPLv3** source-tree
headers and is `dlopen`'d into the GPLv3 apl process, so the **compiled shim + apl combination
is a GPLv3 work**. Apache-2.0 is **one-way compatible into GPLv3**, so shipping the shim
*source* as Apache-2.0 is fine and it combines into a GPLv3 binary at build. This is a stronger
entanglement than gfortran's runtime-exception — surfaced here for the operator's explicit
awareness, not because it blocks.
