# Hash-pinned DEV lockfile for the entity-core-protocol-python peer's TEST suite.
#
# WHY THIS FILE EXISTS (added 2026-09-02)
#   `pyproject.toml` declares pytest under `[project.optional-dependencies] dev`,
#   and the conformance tests `import pytest` at module scope — but pytest was in
#   neither `requirements.txt` nor the toolchain image, so the peer's own test
#   suite could not run in its own container at all:
#
#       ModuleNotFoundError: No module named 'pytest'
#
#   That is the same defect the ghc-toolchain image had on the same day: an image
#   that resolves the LIBRARY closure and not the TEST closure looks complete,
#   the peer builds, and only the gate is missing its dependencies. A declared
#   extra nobody installs is a dependency that does not exist.
#
# SEPARATE FROM requirements.txt ON PURPOSE
#   `requirements.txt` is the SHIPPED runtime closure — exactly one direct
#   dependency (cryptography). Nothing here is shipped in the wheel; folding test
#   tools into the runtime lock would put pytest in the peer's dependency graph
#   for every adopter. Two files, two audiences.
#
# PIN RATIONALE (S11 supply chain: exact version + all published sha256 digests +
# the >=30-day cool-down, same discipline as requirements.txt)
#   pytest 8.4.2  — newest in pyproject's declared `>=8,<9` range.
#   packaging 26.2 and pygments 2.20.0 are DELIBERATELY not the newest releases.
#   26.3 (2026-08-04) and 2.21.0 (2026-08-17) were 29 and 16 days old at pinning
#   and do not clear the cool-down; these are the newest that do.
#
# Install reproducibly with:
#     pip install --require-hashes -r requirements-dev.txt
